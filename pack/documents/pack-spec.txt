Приложение Pack предназначено для того, чтобы помочь путешественникам собрать вещи в дорогу и быстро их находить в чемоданах или рюкзаках во время путешествия а также для согласования "кто что берёт" в группах.

В будущем это приложение станет частью системы Plantour.

Обычно путешественники объединяются в группы для совместного путешествия. Это приложение поможет участникам группы синхронизировать действия во время сбора вещей. Помимо личных вещей используются вещи, используемые более чем одним человеком. Например, большой котёл для приготовления еды на всю группу. 

Приложение Pack может использоваться на всех этапах планирования, подготовки, сборов, проведения и завершения путешествия. Когда оперативный доступ к данным путешествия больше не нужен, оно может быть отправлено в архив и удалено из списка активных путешествий пользователя. В виде архива путешествие доступно в течение длительного времени.


Архитектура данных
==================

Для хранения данных используется схема pack в базе данных Plantour. Pack хранит данные двумя разными способами. Справочные и другие данные хранятся в виде реляционных таблиц. Сборы вещей для путешествия хранятся в виде объектов JSONB. Для поддержки возможности работы оффлайн после каждого внесения изменеий на локальное устройство копируются полные данные путешествия плюс справочники. Возможно, как справочники, так и путешествия будут кэшироваться на клиенте. Когда устройство восстанавливает связь с интернет синхронизация данных с сервером происходит автоматически. Участники группы, работая в оффлайне, могут синхронизировать свои устройства, передавая файлы с помощью внешних носителей или с помощью установки связи между мобильными устройствами.


Таблицы базы данных
===================

- Пользователи (внешняя сущность)
    Управление учётными записями пользователей осуществляется в отдельном приложении, которое является частью Plantour. Чтобы иметь полный доступ к приложению Pack необходимо зарегистрироваться. Ограниченный доступ могут получить путешественники, приглашённые зарегистрированным пользователем для участия в путешествии.

- Путешествия.
    Поездки или походы, для которых осуществляется сбор вещей. Каждый зарегистрированный пользователь может иметь свой собственный список путешествий. Чтобы начать сборы в путешествие, пользователь создаёт новое путешествие в приложении Pack и начинает наполнять его данными. Одно из первых действий пользователя это приглашение других участников путешествия с предоставлением им доступа к данным этого путешествия через уникальный код, предоставляющий разные уровни доступа: полный, только чтение чужих данных, только свои данные. Таблица Путешествия содержит совместно используемые поля, которые доступны для чтения всем путешественникам и для изменения при наличии полного доступа. 

- Единицы измерения
    Используются, например, при подсчёте веса упаковки. Может быть востребовано, например, экстремальными пешеходными туристами.

- Путешественники. 
    Человек, который может принимать участие в путешествии. Не обязательно должен быть зарегистрированным пользователем. Каждый зарегистрированный пользователь может иметь свой собственный список путешественников, он создаётся и поддерживается этим пользователем. Этот список может быть использован как справочник при добавлении путешественников в путешествие.

- Категории вещей путешественника.
    Сущность для группировки вещей: Одежда, Еда, Электроника.

- Вещи путешественника.
    Материальный объект, который принадлежит путешественнику и может понадобиться в путешествии. Ссылается на Категорию вещей. Если для путешествия указана опция "вес вещей обязателен", требует вес. Если путешественник является зарегистрированным пользователем, то этот справочник, как и другие справочники, может быть синхронизирован с их аналогом из собственного аккаунта путешественника.

- Упаковки путешественника.
    Материальный объект, который принадлежит путешественнику и может содержать вещи внутри себя. Вложенные упаковки поддерживаются. Требования по весу те же, что и для вещей. 
 

- Сборы вещей.
    Представляет данные по сбору вещей путешественника в путешествии. Чаще всего это процесс вкладывания вещей в упаковки, но вещь может быть включена в сбор и без упаковки. Ссылается на Путешествия и Путешественников. Содержит JSONB поле для хранения данных по сбору вещей. 
    По умолчанию ответственность за упаковку лежит на её владельце. Но при необходимости ответственным за упаковку может быть назначен другой путешественник, который обязан следить за упаковкой, нести её, грузить в транспорт и не потерять.

Доступ к данным другого юзера
=============================

Владелец путешествия обладает полным доступом ко всему.
Доступ "full" разрешает полный доступ ко всему.
Доступ "read-only" разрешает доступ для чтения ко всему.
Доступ "personal" разрешает полный доступ к своим данным.

Подход к интерфейсу пользователя
================================

Величина, показывающая, насколько интерфейс хорош, обратно пропорциональна умственному напряжению юзера. Самая лучшая прграмма состоит из одной огромной (чтобы не промахнуться) кнопки. Нажимаешь на кнопку - и из щели под кнопкой выскакивают деньги. Качество такого интерфейса можно принять за 100%. 

Интерфейс должен быть предельно простым. За один шаг должна решаться одна простая и понятная юзеру проблема. Во всех местах, где у юзера может возникнуть проблема с пониманием, чего от него хотят, должна появляться ненавязчивая подсказка.

Везде, где это возможно, должен применяться drag-n-drop. Например, для добавления вещей из справочника в упаковку или для перемещения вещи из одной упаковки в другую. По разным причинам drag-n-drop может не работать. Поэтому должен быть предусмотрен альтернативный способ достичь того же результата, что и при работающем drag-n-drop.


Шаблоны и копии путешествий
===========================

Чтобы облегчить и ускорить создание новых путешествий необходимо предусмотреть возможность:
- создания шаблонов типа "Круиз по Средиземноморью", "Турпоход на озеро";
- загрузки шаблонов из файлов, наприрмер, при обмене с другими Pack юзерами;
- копирования данных из уже существующих путешествий;


Архитектура приложения
======================

В путешествиях, особенно вне населённых пунктов, соединение с Интернет часто будет отсутствовать. Поэтому приложение Pack должно оставаться полностью работоспособным в режиме оффлайн, за исключением функций, которые требуют онлайн. Синхронизация между устройствами участников группы должна быть возможна путем обмена файлами, например, через USB flash drives.

На начальном этапе нужно:
- довести до уровня production микросервис для управления юзерами
- создать схему pack в базе данных Plantour с хостингом в Supabase / PostgreSQL
- создать микросервис Pack на базе FastAPI
- создать клиентское приложение PackClient на базе Angular с поддержкой режима PWA


Пример использования приложения
===============================

Семья из четырёх человек решила отправиться в путешествие на природу на три дня. Время года - лето, место - Banff and Jasper National Parks. Папа - Джон, мама - Сильвия, дочь - Лана 17 лет, сын - Том 4 года. Они поедут на собственном SUV из Калгари и будут ночевать в большой палатке. Они заранее приобрели и распечатали билеты в Museums and Historic Sites. Также они планируют приготовить мясо на барбекю. Чтобы собраться в дорогу быстро и качественно они решили воспользоваться приложением Pack.


- Джон наносит визит на сайт pack.plantour.click и регистрируется как пользователь

- Джон создаёт в Pack путешествие в Banff

- Джон создаёт список путешественников и включает в него Сильвию, Лану и Тома.

- Джон переходит на специальную страницу в Pack и посылает Сильвии и Лане email приглашение в путешествие. У Тома своего email пока нет. Вещи Тома соберёт его мама. На другой Pack странице Джон может проверить кому, когда и какие приглашения он посылал.

- Сильвия получает приглашение и переходит по ссылке в письме. Получает возможность создать свой список вещей в дорогу. Ссылка в письме содержит код доступа Сильвии. При необходимости она может ввести этот код вручную чтобы получить доступ к путешествию.

- Сильвия создаёт список своих вещей, включенных в путешествие, параллельно заполняя свой справочник вещей. Этот справочник вещей позднее может быть заново использован в следующем путешествии, созданном Джоном.

- Далее Сильвия добавляет Тома в список путешественников и создаёт для него список вещей, параллельно заполняя его справочник вещей.

- Лана получает приглашение от папы и переходит по предоставленной ссылке на страницу с путешествием в Banff. Создаёт свой список вещей. Некоторые из личных вещей Лана хочет скрыть от посторонних глаз и помечает их как not shown to others. Помеченные таким образом вещи не будут показаны никому, кроме Ланы, но система будет их учитывать, например, при подсчёте общего веса.

- Если Сильвия хочет проконтролировать, всё ли необходимое берёт в дорогу Лана, она легко может это сделать, т.к. у нее есть полный доступ ко всем данным, кроме спрятанных Ланой. Сильвия просит Лану сделать скрытые данные видимыми для неё. Лана использует предоставленный для этого интерфейс и делает данные видимыми для мамы, но скрытыми для остальных.

- Джон создаёт свой список вещей включая вещи общего пользования такие как барбекю и мясо. Когда он добавляет билеты в музей приложение спрашивает его, не следует ли добавить билеты в справочник вещей Джона.

- Джон видит пометки от Сильвии и Ланы, что сборы завершены. Он распечатывает упаковочные листы и метки с QR кодами для каждого места их багажа, добавляет их к упаковкам.

- Грузят автомобиль, отмечая, что уже погружено.

- Выезжают. В дороге интернета нет. Стало холодно и Сильвия использует Pack как PWA приложение на своём телефоне чтобы выяснить, где лежит свитер Джона. Достаёт свитер и делает пометку о том, что свитер теперь не в "Чемодане №2", а вне упаковок. 

- По мере необходимости свои копии приложения на их мобильных устройствах используют Джон и Лана, внося иэменения в локальные данные.

- По завершении путешествия семья возвращается домой и по дороге въезжает в зону где интернет доступен. Каждое из их мобильных устройств автоматически синхронизируется с серверной версией.

- happy end


Все, что было сказано выше, относится к первому этапу - MVP.
