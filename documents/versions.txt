Step 3: Use Conventional Commits
From now on, the way you write your commit messages tells GitHub which part of the X.Y.Z version to increment.

To increment Z (Patch): Use fix: description (e.g., fix: fixed login bug).

To increment Y (Minor): Use feat: description (e.g., feat: added travel map).

To increment X (Major): Add a ! (e.g., feat!: new database structure).


Step 5: Fetching a Version for Dev
If you need to start version 2.24.17 in your local environment, you simply use Git to travel back in time:

Open your terminal in your project folder.

Fetch the latest tags: git fetch --all --tags

Go to that version: git checkout tags/v2.24.17

Start your app: Run npm start and dotnet run. Your code will now be exactly as it was when that version was deployed.
