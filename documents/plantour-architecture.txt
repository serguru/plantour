Plantour архитектура и общий принцип работы 

Supabase PostgreSQL
===================
- Хранение данных, которые должны быть доступны на клиенте в оффлайн режиме. Это справочники (путешественники, вещи, валюты и пр.) и путешествия. Эти данные хранятся в JSONB формате. 
- Хранение реляционных данных приложения, например, кастом данных о юзерах или рассылки приглашений.

.Net C# Plantour API
====================
- Использование Supabase PostgreSQL
- Управление юзерами через Supabase Auth.
- Управление бизнес процессами, которые требуют онлайн. Например, рассылка приглашений в путешествие или построение отчётов.
- Очередь изменений в JSONB объектах через Render Worker. 

Подход к созданию JSON документов
=================================
Вместо того, чтобы работать с одиним большим JSON документом следует создавать и работать с маленькими документами. Большую структуру типа путешествия всегда можно собрать по ссылкам. Каждый JSONB документ должен храниться в своей собственной реляционной таблице.


Обеспечение оффлайн режима
==========================
Данные, которые посылаются на клиент и могут быть изменены в онлайне или оффлайне, представлены в JSON формате. Каждый документ имеет version и updated_at, которые используются при применеии патчей в формате JSON Patch (RFC6902). Каждый патч содержит baseVerrsion. Документы никогда не сравниваются для применения внесенных изменений. Стратегия изменений должна быть такой, чтобы наносить минимально возможный ущерб данным юзера. Конфликты, даже самые критические, всегда разрешаются автоматически. Конкретный алгоритм разрешения конфликтов будет разработан. Ручное разрешение конфликтов не предусматривается. Если патч нельзя применить, он выводится из очереди в добавляется в Dead-Letter Queue. Впоследствии кто-то может решить, что делать с этими патчами.

Клиентское приложение Angular
=============================
- PWA приложение, поддерживает онлайн и оффлайн
- Xранит JSON объекты в IndexedDB
- В онлайне посылает каждое изменение - JSON patch - в API и после подтверждения изменяет локальный JSON
- В оффлайне пишет изменения в локальную очередь в том же формате и затем изменяет локальный JSON
- При появлении интернета автоматически посылает список изменений в API и после их применеия обновляет локальный JSON

Дополнительные возможности
==========================
- Юзер может связать имена медиа файлов на облаке с периодами путешествий. Если юзер загрузит медиа файлы в облако и даст Plantour приложению доступ то эти фото могут быть показаны и звуковые файлы прослушаны внутри Plantour UI в привязке к редевантному периоду путешествия.
