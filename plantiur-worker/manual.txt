
PLANTOUR WORKER PROCESS — TECHNICAL MANUAL
==========================================

1. PURPOSE
----------
Plantour Worker Process is a standalone TypeScript/Node.js background processor
responsible for executing asynchronous tasks originating from other Plantour services.
Its primary initial task is applying JSON changes to stored JSON objects inside a
PostgreSQL database using a resilient, version-controlled merge/update mechanism.

Worker executes tasks stored in the `plantour_jobs` table, using safe concurrency
controls (`FOR UPDATE SKIP LOCKED`). The system is easily extensible to support new
task types.

3. REQUIREMENTS
---------------
- Node.js 18+
- npm or yarn
- PostgreSQL (local or Supabase-hosted)
- Render account (for deployment)

--------------------------------------------------------------------

4. INSTALLATION
----------------

4.1. Clone repository:

    git clone https://github.com/<your-repo>/plantour-worker.git
    cd plantour-worker

4.2. Install dependencies:

    npm install

4.3. Copy environment file:

    cp .env.example .env

4.4. Edit `.env`:

    DATABASE_URL=<your postgres connection string>

--------------------------------------------------------------------

5. INITIAL DATABASE SETUP
-------------------------

Apply SQL scripts to your PostgreSQL database:

    psql "$DATABASE_URL" -f sql/001_create_jobs_table.sql
    psql "$DATABASE_URL" -f sql/002_create_sample_json_tables.sql

(optional)

    psql "$DATABASE_URL" -f sql/003_notify_trigger_example.sql

This creates:

- `plantour_jobs` – universal task queue
- `plantour_json_objects` – demo table for JSON storage

--------------------------------------------------------------------

6. LOCAL DEVELOPMENT
--------------------

6.1. Start Worker:

    npm run dev

This launches worker with `nodemon`, automatically restarting on changes.

6.2. Creating test job:

Insert sample JSON object:

    INSERT INTO plantour_json_objects (data)
    VALUES ('{"name":"Trip 1","country":"Canada"}');

Retrieve its ID:

    SELECT * FROM plantour_json_objects;

Create job:

    INSERT INTO plantour_jobs (task_name, payload, status, attempts, run_at)
    VALUES (
      'apply_json_change',
      '{
        "targetTable": "plantour_json_objects",
        "objectId": "<UUID>",
        "patch": {
          "country": "USA",
          "notes": "Updated",
          "name": null
        }
      }',
      'pending',
      0,
      NOW()
    );

Worker will automatically pick and execute the job.

6.3. Logs:

Logs appear directly in terminal:

    [INFO] ... Processing job ...
    [INFO] ... ApplyJsonChangeTask updated object ...

--------------------------------------------------------------------

7. HOW WORKER EXECUTES TASKS
----------------------------

- Worker checks database every `WORKER_POLL_INTERVAL_MS` milliseconds.
- Reads tasks with status `pending`.
- Locks them using `FOR UPDATE SKIP LOCKED`.
- Updates status to `processing`.
- Executes corresponding task handler.
- If success → status becomes `completed`
- If fail → increments attempts → either retries or sets `dead` after limit.

8. ADDING NEW TASK TYPES
-------------------------

8.1. Create directory:

    src/tasks/myNewTask/

8.2. Create Zod schema:

    types.ts

8.3. Implement task logic:

    MyNewTask.ts

8.4. Register handler in:

    src/core/jobRunner.ts

8.5. Insert jobs:

    INSERT INTO plantour_jobs (task_name, payload, ...) VALUES (...)

Worker will process them automatically.

--------------------------------------------------------------------

9. PRODUCTION DEPLOYMENT ON RENDER
----------------------------------

9.1. Push repository to GitHub.

9.2. In Render Dashboard:
    - New → Worker
    - Select GitHub repo

9.3. Build command:

    npm install && npm run build

9.4. Start command:

    npm run start    (which runs `node dist/index.js`)

9.5. Set environment variables:

    NODE_ENV=production
    DATABASE_URL=postgres://...
    WORKER_POLL_INTERVAL_MS=2000
    WORKER_USE_LISTEN=false

9.6. Deploy.

Render will:
- Build worker
- Run it 24/7
- Restart on crash
- Provide logs

--------------------------------------------------------------------

10. MAINTENANCE & OPERATIONS
----------------------------

10.1. View logs in Render UI.

10.2. Handling failed jobs:
- If status = "failed" → worker retries automatically.
- If status = "dead" → requires manual inspection.

10.3. Recommended monitoring:
- Count of pending tasks
- Number of dead tasks
- Average processing time

--------------------------------------------------------------------

11. FAQ
-------

Q: Worker не стартует?  
A: Проверь DATABASE_URL.

Q: Задание не выполняется?  
A: Проверь payload JSON соответствует Zod-схеме.

Q: Как тестировать быстро?  
A: Вставлять задания напрямую в `plantour_jobs`.

Q: Можно ли иметь несколько воркеров?  
A: Да. Они используют `SKIP LOCKED` и не конфликтуют.
