Оцени идею. Данные хранятся в классических полях таблицы БД. Никаких JSONB полей. Когда пользователь запрашивает данные с сервера динамически формируется JSON response в таком объеме, чтобы если пропадёт интернет, можно было бы полноценно работать, внося изменения в данные. Локальные изменения накапливаются в локальной очереди в виде патчей. Клиент через короткие промежутки времени пытается отослать очередной - один - патч на сервер. Если сервер не смог обработать изменение, то оно остаётся в локальной очереди. В противном случае оно удаляется из очереди. На сервер передаются патчи в которых возможны insert, update и delete операции. Для update операции сервер динамически формирует запрос для изменеия только тех полей, которые указаны в патче.

Оцени идею. Я не могу найти полноценное решение для 100% поддержки оффлайн режима так, чтобы всё работало с приемлемой степенью надёжности. Вместо этого Plantour как PWA в MVP будет обеспечивать readonly оффлайн. Чтобы всегда быть готовым к оффлайну на клиента после каждого изменеия данных будет возвращаться полный набор данных, необходимый для работы. Если клиент послал изменения на сервер и не получил обратно новую версию данных, то это изменеие к клиентским данным не применяется с сообщением "Try again later".
